2. КОМПОНЕНТЫ СИСТЕМЫ
А. Бэкенд-оркестратор (Python + FastAPI)
Функции:
•	Принимает задачу от пользователя.
•	Создает "сессию" (ID задачи).
•	Управляет цепочкой агентов (Аналитик → Разработчик).
•	Хранит состояние агентов (в какой фазе).
•	Отвечает на фронтенд (статусы, сообщения).
Структура БД (SQLite):
sql
-- Таблица проектов (просто папки для группировки)
CREATE TABLE projects (
    id INTEGER PRIMARY KEY,
    name TEXT,
    created_at DATETIME
);

-- Таблица задач (одна задача = один цикл разработки)
CREATE TABLE tasks (
    id INTEGER PRIMARY KEY,
    project_id INTEGER,
    status TEXT, -- 'analytics', 'dev', 'testing', 'done'
    user_prompt TEXT, -- Что вы изначально попросили
    created_at DATETIME
);

-- Таблица сообщений (история диалога агентов и пользователя)
CREATE TABLE messages (
    id INTEGER PRIMARY KEY,
    task_id INTEGER,
    role TEXT, -- 'user', 'analyst', 'developer', 'system'
    content TEXT,
    created_at DATETIME
);

-- Таблица версий кода/ТЗ (для сравнения и отката)
CREATE TABLE artifacts (
    id INTEGER PRIMARY KEY,
    task_id INTEGER,
    type TEXT, -- 'spec' или 'code'
    version INTEGER,
    content TEXT,
    created_at DATETIME
);

1. BPMN-ИНТЕГРАЦИЯ (КЛЮЧЕВОЕ НОВОВВЕДЕНИЕ)
Что это значит для вас:
Вы не просто даете агенту задачу "напиши код". Вы загружаете BPMN-диаграмму процесса, и агенты:
1.	Анализируют процесс (какие шаги, кто участники, какие данные).
2.	Генерируют ТЗ под каждый шаг процесса.
3.	Пишут код для каждого шага (отчеты, обработки, обмены).
4.	Тестируют последовательность шагов.
Пример: Процесс "Согласование счета клиентом"
•	Шаг 1: Аналитик описывает, что должен делать счет на каждом этапе.
•	Шаг 2: Разработчик пишет код для формирования счета.
•	Шаг 3: Аналитик проверяет, соответствует ли код BPMN-логике.
•	Шаг 4: Разработчик правит.
________________________________________
2. ДОПОЛНИТЕЛЬНЫЙ КОМПОНЕНТ — BPMN-ДВИЖОК
Выбор: Camunda 8 (Open Source) или Apache Airflow (для задач)
Функции BPMN-движка:
•	Читает вашу BPMN-диаграмму (XML).
•	Создает "экземпляр процесса" для задачи.
•	Отслеживает статус каждого шага.
•	Передает данные между шагами.
•	Вызывает ИИ-агентов на нужных этапах.
Интеграция с агентами:
text
[Загружена BPMN] → Camunda создает процесс
    ↓
[Шаг 1: "Сбор требований"] → Вызывается Агент-Аналитик
    ↓
[Шаг 2: "Разработка"] → Вызывается Агент-Разработчик
    ↓
[Шаг 3: "Тестирование"] → Вызывается Агент-Тестировщик (новый!)
    ↓
[Шаг 4: "Доработка"] → Цикл до одобрения пользователем

6. НОВЫЕ ТАБЛИЦЫ В БАЗЕ ДАННЫХ (SQLite + доп. связи с 1С)
sql
-- Таблица процессов (BPMN-диаграммы)
CREATE TABLE processes (
    id INTEGER PRIMARY KEY,
    name TEXT,
    bpmn_xml TEXT, -- сама диаграмма
    version INTEGER,
    created_at DATETIME
);

-- Таблица шагов процесса (из BPMN)
CREATE TABLE process_steps (
    id INTEGER PRIMARY KEY,
    process_id INTEGER,
    step_id TEXT, -- ID из BPMN (например, "Task_1")
    name TEXT,
    type TEXT, -- 'userTask', 'serviceTask', 'gateway'
    created_at DATETIME
);

-- Таблица экземпляров задач (вы запустили процесс)
CREATE TABLE task_instances (
    id INTEGER PRIMARY KEY,
    process_id INTEGER,
    status TEXT, -- 'running', 'waiting_analyst', 'waiting_developer', 'done'
    started_at DATETIME,
    finished_at DATETIME
);

-- Таблица связей код ↔ шаг процесса
CREATE TABLE code_artifacts (
    id INTEGER PRIMARY KEY,
    task_instance_id INTEGER,
    process_step_id INTEGER, -- к какому шагу относится код
    code TEXT,
    version INTEGER,
    is_approved BOOLEAN
);

def init_db():
    conn = sqlite3.connect("db/session.db")
    cursor = conn.cursor()
    
    # Таблица проектов
    cursor.execute("""
        CREATE TABLE IF NOT EXISTS projects (
            id TEXT PRIMARY KEY,
            name TEXT,
            created_at DATETIME
        )
    """)
    
    # Таблица задач
    cursor.execute("""
        CREATE TABLE IF NOT EXISTS tasks (
            id TEXT PRIMARY KEY,
            project_id TEXT,
            status TEXT,
            user_prompt TEXT,
            spec TEXT,
            code TEXT,
            test_result TEXT,
            created_at DATETIME,
            updated_at DATETIME,
            FOREIGN KEY (project_id) REFERENCES projects (id)
        )
    """)
    
    # Таблица сообщений (история)
    cursor.execute("""
        CREATE TABLE IF NOT EXISTS messages (
            id TEXT PRIMARY KEY,
            task_id TEXT,
            role TEXT,
            content TEXT,
            created_at DATETIME,
            FOREIGN KEY (task_id) REFERENCES tasks (id)
        )
    """)
    
    conn.commit()
    conn.close()

init_db()

@app.post("/api/tasks")
async def create_task(task: TaskCreate):
    """Создать новую задачу"""
    task_id = str(uuid.uuid4())
    conn = sqlite3.connect("db/session.db")
    cursor = conn.cursor()
    
    # Создаем проект, если не существует
    cursor.execute("SELECT id FROM projects WHERE name = ?", (task.project_name,))
    project = cursor.fetchone()
    if not project:
        project_id = str(uuid.uuid4())
        cursor.execute(
            "INSERT INTO projects (id, name, created_at) VALUES (?, ?, ?)",
            (project_id, task.project_name, datetime.now())
        )
    else:
        project_id = project[0]
    
    cursor.execute(
        """INSERT INTO tasks (id, project_id, status, user_prompt, created_at, updated_at) 
           VALUES (?, ?, ?, ?, ?, ?)""",
        (task_id, project_id, "created", task.prompt, datetime.now(), datetime.now())
    )
    
    # Добавляем сообщение пользователя
    cursor.execute(
        "INSERT INTO messages (id, task_id, role, content, created_at) VALUES (?, ?, ?, ?, ?)",
        (str(uuid.uuid4()), task_id, "user", task.prompt, datetime.now())
    )
    
    conn.commit()
    conn.close()
    
    return {"id": task_id, "status": "created"}

import json
import requests
from config import OLLAMA_HOST, MODEL_NAME
import logging

logger = logging.getLogger("ai_workstation")

class BaseAgent:
    def __init__(self, task_id):
        self.task_id = task_id
        self.model = MODEL_NAME
        self.ollama_url = f"{OLLAMA_HOST}/api/generate"
    
    def call_llm(self, prompt, system_prompt=None):
        """Вызов LLM через Ollama"""
        full_prompt = f"{system_prompt}\n\n{prompt}" if system_prompt else prompt
        
        payload = {
            "model": self.model,
            "prompt": full_prompt,
            "stream": False,
            "options": {
                "temperature": 0.3,
                "max_tokens": 4096
            }
        }
        
        try:
            response = requests.post(self.ollama_url, json=payload, timeout=120)
            if response.status_code == 200:
                result = response.json()
                return result.get("response", "")
            else:
                logger.error(f"Ошибка LLM: {response.status_code} - {response.text}")
                return f"Ошибка вызова модели: {response.status_code}"
        except Exception as e:
            logger.error(f"Исключение при вызове LLM: {str(e)}")
            return f"Ошибка: {str(e)}"

from .base_agent import BaseAgent
import chromadb
from chromadb.utils import embedding_functions
import os
import logging

logger = logging.getLogger("ai_workstation")

class AnalystAgent(BaseAgent):
    def __init__(self, task_id):
        super().__init__(task_id)
        # Инициализация RAG (база знаний)
        self.chroma_client = chromadb.PersistentClient(path="./db/chroma")
        self.embedding_fn = embedding_functions.SentenceTransformerEmbeddingFunction(
            model_name="paraphrase-multilingual-MiniLM-L12-v2"
        )
        
        # Создаем или получаем коллекцию
        try:
            self.collection = self.chroma_client.get_collection("knowledge_base")
        except:
            self.collection = self.chroma_client.create_collection(
                name="knowledge_base",
                embedding_function=self.embedding_fn
            )
        
        # Индексируем существующие ТЗ
        self._index_specs()
    
    def _index_specs(self):
        """Индексация старых ТЗ из папки dataset/approved"""
        spec_dir = "./dataset/approved"
        if not os.path.exists(spec_dir):
            return
        
        spec_files = [f for f in os.listdir(spec_dir) if f.startswith("spec_")]
        
        for i, file in enumerate(spec_files):
            with open(os.path.join(spec_dir, file), "r", encoding="utf-8") as f:
                content = f.read()
            
            # Проверяем, есть ли уже такой документ
            try:
                self.collection.get(ids=[file])
            except:
                self.collection.add(
                    documents=[content],
                    metadatas=[{"source": file}],
                    ids=[file]
                )
    
    def _search_similar_specs(self, query, n_results=3):
        """Поиск похожих ТЗ в базе знаний"""
        try:
            results = self.collection.query(
                query_texts=[query],
                n_results=n_results
            )
            return results["documents"][0] if results["documents"] else []
        except Exception as e:
            logger.warning(f"Ошибка поиска в RAG: {str(e)}")
            return []
    
    def process(self, prompt):
        """Генерация ТЗ"""
        logger.info(f"Аналитик обрабатывает запрос: {prompt[:100]}...")
        
        # Ищем похожие ТЗ
        similar_specs = self._search_similar_specs(prompt)
        
        # Формируем контекст
        context = ""
        if similar_specs:
            context = "Примеры похожих технических заданий:\n\n"
            for i, spec in enumerate(similar_specs, 1):
                context += f"Пример {i}:\n{spec[:500]}...\n\n"
        
        system_prompt = """Ты — ИИ-аналитик по 1С-разработке. 
        Твоя задача — написать детальное техническое задание (ТЗ) для разработчика 1С.
        ТЗ должно содержать:
        1. Цель разработки
        2. Функциональные требования
        3. Структуру данных (регистры, справочники, документы)
        4. Алгоритмы и бизнес-логику
        5. Форматы отчетов или обработок
        6. Требования к интерфейсу
        
        Пиши на русском языке, структурированно, используй маркдаун.
        """
        
        user_prompt = f"""
        Запрос пользователя: {prompt}
        
        {context}
        
        Напиши подробное техническое задание для 1С-разработчика на основе запроса пользователя.
        """
        
        # Генерируем ТЗ
        spec = self.call_llm(user_prompt, system_prompt)
        
        return spec

import argparse
import json
import requests
import sys

API_URL = "http://localhost:8000"

def create_task(prompt):
    """Создать задачу через CLI"""
    response = requests.post(f"{API_URL}/api/tasks", json={
        "prompt": prompt,
        "project_name": "CLI-Project"
    })
    if response.status_code == 200:
        task = response.json()
        print(f"✅ Создана задача: {task['id']}")
        return task['id']
    else:
        print(f"❌ Ошибка: {response.text}")
        return None

def run_agent(task_id, agent_type):
    """Запустить агента"""
    endpoints = {
        "analyst": f"/api/tasks/{task_id}/run_analyst",
        "developer": f"/api/tasks/{task_id}/run_developer",
        "tester": f"/api/tasks/{task_id}/run_tester",
        "chain": f"/api/tasks/{task_id}/run_chain"
    }
    
    endpoint = endpoints.get(agent_type)
    if not endpoint:
        print("❌ Неизвестный тип агента")
        return
    
    response = requests.post(f"{API_URL}{endpoint}")
    if response.status_code == 200:
        print(f"✅ {agent_type} завершил работу")
        result = response.json()
        print(json.dumps(result, indent=2, ensure_ascii=False))
    else:
        print(f"❌ Ошибка: {response.text}")

def get_task(task_id):
    """Получить задачу"""
    response = requests.get(f"{API_URL}/api/tasks/{task_id}")
    if response.status_code == 200:
        task = response.json()
        print(json.dumps(task, indent=2, ensure_ascii=False))
    else:
        print(f"❌ Ошибка: {response.text}")

def main():
    parser = argparse.ArgumentParser(description="AI-Coder Workstation CLI")
    subparsers = parser.add_subparsers(dest="command", help="Команды")
    
    # Создать задачу
    create_parser = subparsers.add_parser("create", help="Создать задачу")
    create_parser.add_argument("--prompt", required=True, help="Описание задачи")
    
    # Запустить агента
    run_parser = subparsers.add_parser("run", help="Запустить агента")
    run_parser.add_argument("--task", required=True, help="ID задачи")
    run_parser.add_argument("--agent", choices=["analyst", "developer", "tester", "chain"], 
                           required=True, help="Тип агента")
    
    # Получить задачу
    get_parser = subparsers.add_parser("get", help="Получить задачу")
    get_parser.add_argument("--task", required=True, help="ID задачи")
    
    args = parser.parse_args()
    
    if args.command == "create":
        create_task(args.prompt)
    elif args.command == "run":
        run_agent(args.task, args.agent)
    elif args.command == "get":
        get_task(args.task)
    else:
        parser.print_help()

if __name__ == "__main__":
    main()

import speech_recognition as sr
import pyttsx3
import sys

def speech_to_text(language="ru-RU"):
    """Преобразование голоса в текст"""
    recognizer = sr.Recognizer()
    with sr.Microphone() as source:
        print("🎤 Слушаю... Говорите!")
        try:
            audio = recognizer.listen(source, timeout=5, phrase_time_limit=10)
            print("🔄 Распознаю...")
            text = recognizer.recognize_google(audio, language=language)
            print(f"📝 Распознано: {text}")
            return text
        except sr.WaitTimeoutError:
            print("⏰ Время ожидания истекло")
            return None
        except sr.UnknownValueError:
            print("❌ Не удалось распознать речь")
            return None
        except Exception as e:
            print(f"❌ Ошибка: {str(e)}")
            return None

def text_to_speech(text, voice="ru"):
    """Озвучивание текста"""
    try:
        engine = pyttsx3.init()
        engine.say(text)
        engine.runAndWait()
    except Exception as e:
        print(f"❌ Ошибка озвучивания: {str(e)}")

if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--speak":
        text = " ".join(sys.argv[2:])
        text_to_speech(text)
    else:
        text = speech_to_text()
        if text:
            print(f"Результат: {text}")

Проанализировав предоставленные ссылки, я вижу, что это не просто отдельные инструменты, а три взаимодополняющих слоя, которые формируют полноценную экосистему для разработки 1С с ИИ. Это именно то, что нам нужно для «Цифрового работника».

1. mcp-bsl-platform-context: Справочник по платформе 1С (База знаний)
Суть: MCP-сервер, который предоставляет ИИ-агенту доступ к справочной информации по синтаксису, объектной модели и встроенным функциям 1С. Это как «Синтакс-помощник», но в виде инструмента для ИИ.
Применимость к вашему проекту (Очень высокая):
•	Для агента-Аналитика: Он сможет не просто генерировать ТЗ, но и проверять его на реализуемость. Например, перед тем как предложить использовать метод СтрНайти(), он может уточнить его сигнатуру и параметры.
•	Для агента-Разработчика: Агент будет писать код с гарантией корректного синтаксиса, сверяясь с актуальной документацией платформы. Это снизит количество ошибок в генерируемом коде.
•	Способ установки: Запускается как отдельный Java-сервис (JAR-файл) и подключается к вашему клиенту (Claude Desktop, Cursor) через MCP. Это легковесное решение, которое можно развернуть на рабочей станции или сервере.
________________________________________
2. rlm-tools-bsl: Анализ кодовой базы 1С (Глаза и руки)
Суть: Это RLM-сервер (Repository-Level Machine-coding). В отличие от RAG, он не требует предварительной векторизации всей базы. Он дает агенту более 50 инструментов для детерминированного, точечного анализа исходников 1С (BSL-модулей, XML-форм, метаданных). Агент сам пишет короткие Python-скрипты, которые через этот MCP-сервер выполняют поиск и извлекают только нужные фрагменты кода.
Применимость к вашему проекту (Критически важная):
•	Решение главной боли: Вы работаете с большими конфигурациями 1С (ERP, УТ). Агент без такого инструмента будет «читать» файлы по 2000 строк, тратя огромное количество токенов и запутываясь. С rlm-tools-bsl он экономит токены в разы и получает точные данные.
•	Реальные сценарии:
o	«Найди все места, где используется документ РеализацияТоваровУслуг.»
o	«Покажи граф вызовов для процедуры РассчитатьСкидки.»
o	«Найди все расширения, которые перехватывают типовой метод.»
o	«Какую структуру имеет форма справочника "Контрагенты"?»
•	Интеграция: Ставится через pip install rlm-tools-bsl и запускается как локальный MCP-сервер. Поддерживает работу с выгрузками CF, EDT и CFE-расширениями.
________________________________________
3. ai_rules_1c: Набор правил и методология (Мозг и дисциплина)
Суть: Это не инструмент, а портативный набор правил, субагентов и слэш-команд для ИИ-агентов. Он структурирует работу агента: как писать код, как проводить ревью, как использовать MCP-инструменты, какие есть архитектурные паттерны и анти-паттерны. По сути, это готовый «инженерный контекст» для агента.
Применимость к вашему проекту (Стратегически важная):
•	Это готовые «Навыки» (Skills) для 1С. Мы искали способ создать и накапливать навыки. Этот репозиторий — огромная база таких навыков, отформатированная для автоматической установки в проект. Он уже содержит правила для Cursor, Claude Code, OpenCode и других агентов.
•	Методология и дисциплина: Он решает проблему, с которой вы столкнулись (агент не слушает системный промпт). В ai_rules_1c жестко прописана дисциплина MCP-first поиска, процедура разработки, политика безопасности и стандарты кода.
•	Для вашего «Цифрового работника»: Вы можете интегрировать этот подход. Вместо того чтобы вручную писать правила в системный промпт, вы даете агенту доступ к этим правилам. Тогда он будет действовать как профессионал, а не как «болтун».
